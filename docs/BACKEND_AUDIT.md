# CollegeBites — Backend Audit Report

## 1. Scope & Inventory
- **Framework:** FastAPI + SQLAlchemy 2.0 + Alembic + Pydantic v2 + ReportLab + OpenPyXL + Celery/Redis.
- **Total Mounted ASGI Routes:** **412 routes** across **35 routers** (`402` `/api/v1/*` HTTP endpoints + `6` root/health/OpenAPI routes + `4` WebSocket routes under `/api/v1/ws/*`) backed by **132 SQLAlchemy tables**.
- **Alembic Schema Head:** Single clean head `f6a7b8c9d0e1` (`f6a7b8c9d0e1_razorpay_only_and_live_otp.py`, chaining cleanly off `e5f6a7b8c9d0` which creates lock-free PostgreSQL sequences `order_number_seq` and `invoice_number_seq`).
- **Payment & Auth Policy Compliance:** Razorpay-only online payments (Stripe fully removed while preserving historical payment/ledger records) + Live OTP Authentication (`dev_otp` and `OTP_TEST_ECHO` permanently removed; real SMTP/Resend/SendGrid/SMS delivery enforced).

## 2. Critical Defects Identified & Remediated During Audit (Phases 35–37)
| # | File & Location | Finding | Resolution Applied |
|---|---|---|---|
| 1 | `backend/app/services/order_service.py` & `invoice_service.py` | Global `pg_advisory_xact_lock` serialized checkouts/invoices; sequence fallback lacked a PostgreSQL `SAVEPOINT` risking `InFailedSqlTransaction`. | Replaced with lock-free PostgreSQL `nextval('order_number_seq')` / `nextval('invoice_number_seq')` wrapped in `with db.begin_nested():` savepoints + thread-safe SQLite fallback. |
| 2 | `backend/app/services/production_service.py` (`list_recipes`, `upsert_recipe`) | Referenced nonexistent `Recipe.instructions` attribute (`Recipe` model defines `notes`), causing `AttributeError`/`TypeError` runtime crashes; `inventory_manager` could self-verify recipes. | Fixed to `rec.notes` (preserving JSON `instructions` key), enforced `403` for non-approver `verify=True`, reset `is_verified=False` on ingredient edits, filtered planning by `CollegeEvent.event_date` & `ProductionPlan.plan_date`, upgraded QC gate to require the **latest** QC check to pass, and restored allocated stock on pre-cooking cancellation. |
| 3 | `backend/app/api/queue/routes.py` (`GET /queue/canteens/{id}`) | Unauthenticated callers received `active_orders_queue` & `delayed_orders` containing customer names (`customer_name` PII leak); `/queue/orders/{id}` omitted `estimated_pickup_at` & `last_updated_at`. | Restricted `active_orders_queue`/`delayed_orders` strictly to authenticated canteen-scoped staff; public callers receive aggregate metrics + `congestion_warnings` only; added `estimated_pickup_at`, `last_updated_at`, `waiting_time_available`, and `"Waiting time currently unavailable."`. |
| 4 | `backend/app/services/inventory_service.py` & `api/inventory/routes.py` | `inventory_manager` could bypass manager approval by creating POs with `initial_status="ordered"` or transitioning unapproved `draft`/`pending_approval` POs directly to `"ordered"`; unusable (`blocked`/`rejected`/`recalled`) batches were counted as available stock. | Enforced `can_approve` RBAC (`403`) on both PO creation (`approved`/`ordered`) and unapproved transitions to `"ordered"`; excluded `blocked`/`rejected`/`recalled` batches alongside expired batches in `_expired_batch_totals_map`; auto-fulfilled linked `ReorderRecommendation` on full GRN. |
| 5 | `backend/app/services/notification_service.py` & `api/realtime/routes.py` | Setting `in_app_enabled=False` aborted external email/SMS delivery; marking shared role/broadcast alerts read muted them for all users; `food_safety_inspector` was excluded from `/realtime/notifications/stream`. | Added `channel="external"` external dispatch when in-app is off, per-user read tracking in `metadata_json["read_by_user_ids"]`, `super_admin` visibility on `college_admin` alerts, canteen scope checks on read/retry, `offset` pagination on deliveries, and `food_safety_inspector` SSE access. |
| 6 | `backend/app/services/food_safety_service.py` & `api/food_safety/routes.py` | `canteen_manager` could create global templates (`canteen_id=None`); no `PATCH`/`DELETE` template endpoints; recurring cleaning tasks did not auto-schedule next occurrence; dashboard missed overdue tasks/open incidents outside `days` window. | Blocked non-admin global templates (`403`), added template `PATCH`/`DELETE`, added automatic next-occurrence scheduling for daily/weekly/monthly cleaning tasks, enforced incident state/resolution guards + `GET /incidents/{id}/audit-history`, and counted all currently overdue tasks/open incidents. |
| 7 | `backend/app/services/reorder_service.py` & `traceability_service.py` | Reorder scan lacked consumption-spike detection and cross-day pending-draft deduplication; `create_draft_po_from_recommendation` committed in two transactions; recall/quality changes did not refresh dish sufficiency. | Added 3-day vs 14-day consumption-spike trigger, pending draft PO deduplication, single-transaction atomic draft PO (`commit=False`), batch `movements` endpoint, 3-day bounded order trace window, and `refresh_food_item_ingredient_sufficiency` on quality/recall updates. |
| 8 | `backend/app/services/report_service.py`, `forecast_service.py`, `ai_assistant_service.py` | BI exports dropped filters & financial/comparison sections; consumption trends omitted `production_use`; filtered margin subtracted whole-canteen costs; AI Assistant leaked `₹` revenue/loss to kitchen/inspector roles and missed write verbs. | Fixed filtered revenue (`OrderItem.line_total`) & margin scope notice, added `production_use` consumption tracking, forwarded all filters + financial/comparison blocks into CSV/PDF/XLSX exports, added IQR outlier winsorization & `/forecasting/canteens/{id}/evaluations`, enforced finance/forecast RBAC + expanded write-action blocker + `"calculated"` classification in AI Assistant. |
| 9 | `backend/app/main.py`, `security_headers.py`, `core/logging.py`, `backup_service.py` | `X-Request-ID` mismatch between outer observability middleware (16-hex) and inner `SecurityHeadersMiddleware` (36-UUID), plus duplicate `X-Process-Time-Ms`; PostgreSQL restore did not resync sequences. | Unified canonical `X-Request-ID` via `scope["state"]["request_id"]` and `contextvars.ContextVar` injected into all JSON/text log records, removed duplicate `X-Process-Time-Ms`, and added PostgreSQL `setval` sequence resync after restore. |

## 3. Concurrency, Idempotency & Data Integrity Verification
- **Inventory & Batch Locking:** `reserve_inventory_for_order`, `deduct_inventory_for_order`, `allocate_stock_batches`, and `receive_purchase_order` acquire row locks (`SELECT ... FOR UPDATE`) in canonical sorted order to prevent deadlocks and negative stock.
- **Duplicate Prevention:** Checkout `Order.idempotency_key`, webhook `PaymentWebhookEvent(provider, event_id)`, GRN `GoodsReceipt.idempotency_key`, production batch `ProductionBatch.idempotency_key` + single-allocation guard, daily `ReorderRecommendation.idempotency_key` + atomic single-draft-PO lock, and `Notification.dedup_key` / `event_id`.
- **No Fake Data & No Refunds:** Verified across all 35 routers; zero refund routes exist, zero coupon/discount mutation routes exist, and all analytics/compliance/forecast endpoints return explicit empty/insufficient states when DB records are absent.
